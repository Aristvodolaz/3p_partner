# Тестирование 3P Partner

Как запускать тесты и чем покрыт проект. Актуально на 2026-10-01.

## Как запускать

| Слой | Каталог | Команда |
|---|---|---|
| Backend (NestJS) | `backend/` | `npm test` (Jest) |
| Web (React/Vite) | `frontend/` | `npm test` (Vitest) |
| Android (Kotlin) | `mobil/` | `./gradlew :core:network:test` |

## Стек (определён по проекту, не навязан)

- **Backend** — NestJS + Prisma (MSSQL). Тесты: **Jest** + `@nestjs/testing`, Prisma/Storage/Numbering мокаются, БД не нужна.
- **Web** — React 18 + Vite + TS. Тесты: **Vitest** (естественно для Vite) + jsdom + @testing-library/react.
- **Android** — Kotlin, многомодульный (`core:*`, `feature:*`), Jetpack Compose. Тесты: **JUnit 4** в чистых JVM-модулях.
- **E2E (Web)** — Playwright MCP (подключён).

## Ограничения окружения (объективные)

- **Внешняя авторизация недоступна.** `POST /auth/login` проксирует во внутренний
  сервис сотрудников НПП, который из этого окружения отдаёт **503**. Поэтому
  авторизованные E2E-сценарии (и Web, и Android) здесь прогнать нельзя — доступен
  только экран входа и его валидация. E2E нужно гонять в сети с доступом к auth.
- **Только продакшен-БД.** Backend настроен на прод-MSSQL; тестовой/Docker-БД нет.
  Поэтому API-integration тесты с реальной записью не настроены намеренно
  (запрет деструктивных операций против прод-БД). Путь для них: поднять MSSQL в
  Docker, прогнать миграции `prisma/migrations/*.sql`, указать `DATABASE_URL` на него.
- **Maestro (Android E2E).** Нет нативной сборки под Windows; путь — WSL + `usbipd`
  для проброса USB-устройства, либо нативная поддержка Maestro в будущем. На машине
  есть WSL/Ubuntu. Как рабочая альтернатива в этом окружении Android-UI проверялся
  напрямую через `adb` (uiautomator dump / input tap / screencap) на реальном
  устройстве `WCR7N19111000970`.
